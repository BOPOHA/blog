I recently added a **4TB Seagate IronWolf** HDD to my ThinkCentre Server to serve as a dedicated video storage and torrenting machine. To get the most out of the spinning rust, I needed a setup that minimizes fragmentation and network latency.

Here is the complete, non-interactive configuration guide for **Fedora 43 Server**, moving from a raw disk to a fully tuned streaming stack. All commands are executed as **root**.

## The Hardware
* **Disk:** Seagate IronWolf 4TB (SATA, 5400RPM) in a USB/UAS enclosure
* **OS:** Fedora Linux 43 (Server Edition)
* **Mount Point:** `/srv/TORRENT`

---

### Step 1: Partitioning & Formatting
Since the drive is larger than 2TB, we must use GPT. We use `sgdisk` for non-interactive partitioning and `mkfs.ext4` with specific flags to optimize for large video files.

**Key Flags:**
* `-m 0`: Sets reserved blocks to 0% (reclaiming ~200GB of space usually reserved for root).
* `-T largefile4`: Reduces inode count, optimizing the filesystem structure for large files rather than millions of tiny ones.

```bash
# 1. Wipe existing filesystem signatures to prevent conflicts
wipefs -a /dev/sdb

# 2. Create a new GPT table with a single partition filling the disk
# -n 1:0:0 (New partition 1, start default, end default)
# -t 1:8300 (Type Linux Filesystem)
sgdisk -n 1:0:0 -t 8300 /dev/sdb

# 3. Inform the kernel of changes
partprobe /dev/sdb

# 4. Format with Large File optimization
mkfs.ext4 -m 0 -T largefile4 /dev/sdb1

```

### Step 2: Persistent USB Mount (with automount)

The USB disk currently appears as `/dev/sda1`, but device names can change. Mount by UUID instead. The `nofail` option lets the machine boot without the disk; `x-systemd.automount` creates an on-demand mount, so systemd mounts the disk on the first access to `/srv/TORRENT`. `x-systemd.device-timeout=10s` prevents a missing USB disk from holding boot up for long.

`data=ordered` is deliberately not specified: it is ext4's default data mode.

```bash
# 1. Create the mount point
mkdir -p /srv/TORRENT

# 2. Confirm the filesystem UUID (the current disk is /dev/sda1)
blkid /dev/sda1

# 3. Add this single line to /etc/fstab. Do not leave an older active
# TORRENT line behind. `noatime` avoids writes for read-only access;
# `lazytime` batches atime/mtime updates.
UUID=a0d45e17-4bf3-46bf-8b4e-b0f9ab5322ec /srv/TORRENT ext4 nofail,x-systemd.automount,x-systemd.device-timeout=10s,noatime,lazytime 0 2

# 4. Regenerate units from fstab and test the entry
systemctl daemon-reload
mount -av
findmnt /srv/TORRENT

# 5. FIX PERMISSIONS (Critical Step)
# By default, the mount point is owned by root. We must give it to transmission.
chown -R transmission:transmission /srv/TORRENT
chmod 775 /srv/TORRENT

# 6. Create directory structure
# Since we just changed ownership, these will be created as transmission:transmission
mkdir -p /srv/TORRENT/{inbox,new,family}

```

To check the generated units, use:

```bash
systemctl status srv-TORRENT.automount
systemctl status srv-TORRENT.mount
```

The directory `/srv/TORRENT` may exist even when the filesystem is absent, so do not use a `PathExists=` unit to detect that the drive is mounted. Use `findmnt /srv/TORRENT` when checking manually.

### Step 2a: Restart storage consumers after a reconnect (optional)

On this Fedora host, Transmission is `transmission-daemon.service` and Samba is `smb.service`. Confirm the local names before installing this optional hook:

```bash
systemctl list-unit-files 'transmission*' 'smb*'
systemctl is-active transmission-daemon.service smb.service
```

The following one-shot unit is started by the real mount unit after every successful mount. This is useful after a USB disconnect/reconnect: it refreshes Samba and makes Transmission reopen its storage paths. It uses `try-restart`, so it does not unexpectedly enable a service that an administrator intentionally stopped.

```bash
cat > /etc/systemd/system/torrent-drive-services.service <<'EOF'
[Unit]
Description=Restart torrent storage consumers after TORRENT mounts
After=srv-TORRENT.mount

[Service]
Type=oneshot
ExecStart=/usr/bin/systemctl try-restart transmission-daemon.service smb.service
EOF

# Attach the action to the generated fstab mount unit. Do not add
# RequiresMountsFor=/srv/TORRENT to torrent-drive-services.service here:
# the mount already starts this service, and that reverse dependency is unnecessary.
systemctl edit srv-TORRENT.mount
```

Add this drop-in content in the editor:

```ini
[Unit]
Wants=torrent-drive-services.service
```

Then reload systemd:

```bash
systemctl daemon-reload
```

Do **not** enable `torrent-drive-services.service`: it has no `[Install]` section and is intentionally started by `srv-TORRENT.mount`, not at an unrelated boot point. Do not use a `PathExists=/srv/TORRENT` watcher—an automount leaves the directory present while its filesystem is not mounted.

### Step 3: Transmission Daemon Setup

We are using the system-wide `transmission-daemon`. By default, the configuration directory might be empty, so we will generate a full, optimized `settings.json` file.

**Optimizations:**

* `preallocation: 2` (Full): Allocates full file space on download start. Essential to prevent fragmentation on HDDs.
* `cache-size-mb: 256`: Increases write cache to smooth out I/O spikes.

### Step 4: Samba (SMB) Configuration
We configure Samba to share the directory as **Read-Only**.

**Note:** We set `force user = transmission` to ensure that you can access files created by the torrent client without permission errors.

```bash
# 1. Backup existing config
cp /etc/samba/smb.conf /etc/samba/smb.conf.bak

# 2. Append the Read-Only share definition
# Note: We use 'aio' (Asynchronous I/O) settings to improve read performance for large files.
cat <<EOF >> /etc/samba/smb.conf

[VideoArchive]
   path = /srv/TORRENT
   browseable = yes
   read only = yes
   guest ok = yes
   force user = transmission
   aio read size = 16384
   aio write size = 16384
EOF

# 3. Restart Samba
systemctl enable --now smb
```

### Step 5: SELinux & Permissions (Fedora Specific)
Fedora enforces strict security. By default, it will block Samba from accessing `/srv`. We must update the security context and ensure user permissions allow directory traversal.

```bash
# 1. Allow Samba to read/write the torrent directory in SELinux
# (Requires policycoreutils-python-utils)
semanage fcontext -a -t samba_share_t "/srv/TORRENT(/.*)?"
restorecon -R -v /srv/TORRENT
setsebool -P allow_transmission_anon_write 1

# 2. Add your user to the transmission group for easy access
usermod -a -G transmission think

# 3. Create a Samba password for your user (required for private shares)
smbpasswd -a think
```

### Step 6: Migrating Old Data (Optional)
If you are moving data from an old drive (e.g., `/srv/TORRENT_OLD`), **do not use `cp`**. 
Standard copy commands do not pre-allocate space, which will immediately fragment your fresh drive.

Instead, use `rsync` with the `--preallocate` flag to ensure large video files are written contiguously.

```bash
# 1. Stop Transmission to release file locks
systemctl stop transmission-daemon

# 2. Copy with Preallocation
# -a: Archive mode (preserves permissions/times)
# -h: Human readable numbers
# -W: Whole file (faster for local copies)
# --preallocate: The magic flag to prevent fragmentation
# --info=progress2: Shows a single total progress bar
rsync -ahW --info=progress2 --preallocate /srv/TORRENT_OLD/ /srv/TORRENT/

# 3. Restart Transmission
systemctl start transmission-daemon
```
