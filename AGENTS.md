# Blog authoring instructions

- Keep each post self-contained in one Markdown file under `content/posts/`.
- Include all article content, code examples, configuration, policy data and
  other supporting material needed by the reader inside that Markdown file.
- Do not create companion scripts, data files, images, diagrams or other
  per-post assets. Use fenced code blocks and Markdown tables inside the post.
- Temporary files extracted to verify examples belong outside this repository
  (for example, under `/tmp`) and must not be committed as post assets.
- Preserve unrelated posts and drafts. Change shared site files only when the
  requested task requires it.

These rules apply to the current consent article and future posts.
